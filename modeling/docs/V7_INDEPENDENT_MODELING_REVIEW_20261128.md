## 二、仍围绕原有两条公式，不以新增模型替代论证

原论文版本、页码、符号、前提及此前全文阅读记录见 `V6_MODELING_DERIVATION_20261127.md` §2：

1. P1，Peyhardi 等 arXiv:1404.7331v2，PDF p4 §3.1 式(1)及紧接的未编号 `r(π)=F(Zβ)`；本题二分局部结点适配为 logistic 链接。
2. P2，同作者 arXiv:1405.5802v1，PDF p5 Definitions 1/2 后的未编号树路径乘积；叶概率为各路径条件概率之积。

本轮重读既有推导记录并检查实现，**没有新增这两篇的全文阅读声明**。P1 的条件观测独立前提仍未证明适用于航班；P2 的概率链式分解不需要假定各扰动事件独立。

### 2.1 从信息集改变到 v7 的适配

令 X 为 BTS 报送表中的排班属性代理，W 为始发站 TAF prevailing 特征，U=0 为已知结局。对于固定阈值 t，联合目标为取消、非取消改航、正常完成且到达延误至少 t 的互斥并集；不能把取消航段填一个虚构延误值。

v7 的天气消融只沿用 F1 的二分直接联合模型：静态模型输入 X，增强模型输入 (X,W)，各自用原校准窗口拟合 sigmoid 校准。代码 `fit_weather_models` 在两个分支间固定**相同训练抽样行、校准行和测试行**，C、seed、特征编码、缺失处理仍是已声明的工程选择，并非论文证明的最优参数。

因此这个适配回答的是：在约束的信息代理与可匹配总体内，加入这些归档预报字段是否改变评分？不是天气的因果作用，不是与已选历史树模型的直接优劣比较，更不是购票时完整信息的替身。

### 2.2 F2 为什么仍是同卡一致性的结构基准

对共享五叶，`p15=p60+π(15≤D<60,正常完成)`，故非负叶质量自动保证 p15≥p60；这是分区恒等式，不是需要拟合验证的事件独立假设。

天气消融的两个阈值分别拟合，并没有通过 F2 共享同一个叶分布。新增 `audit_weather_thresholds_v7.py` 重新构造原天气拟合、按稳定航段身份配对并保留原概率：

- 2026-01 至 08：两种天气对照方法各 **1,373,557** 条，均 0 倒置；增强模型最接近边界的 `p60-p15=-0.0106627141`。
- 已看 2026-09：两种方法各 170,657 条，也为 0。
- 严格检测 `p60-p15>1e-12`；没有裁剪、排序或事后投影。原始全部配对预测另存工作区，包内保留逐月指纹、全量倒置明细空表及逐文件哈希清单。

**观察到 0 不等于结构保证，也不批准同卡上线**。若以后做共享天气五叶，须先冻结候选、保留当前反例检查，在真正后续未看结果上比较；不能用本轮已看的八个月再次宣称盲测。既有 v6 四条“方法—航段”倒置仍保留，不能用本次 0 覆盖旧反例。

## 三、先查信息时点和分母，再解释分数

### 3.1 时点规则的可核内容与不可核内容

原算法：始发地 IANA 时区转换 BTS 本地计划时间，模拟决策点为起飞前 120 分钟；再加 30 分钟档案发行缓冲，以 `available_utc≤scheduled_utc−150min` 选当时最新产品，再检查有效段覆盖计划起飞（右端不含）。最新版本无效时不回退旧报。2400 及夏令时不存在/歧义时间保留为不可匹配。

这些是**工程保守规则和排班代理**。检查代码及结果确证最短时间间隔 150 分钟；但 available_utc 是发行/报头等时间的较晚者，并非真实用户接收日志。30 分钟不能证明传输延迟一定不超过它；计划起飞也不是实际订票时抓取的排班版本。不得写成“已消除一切信息泄漏”。

原协议本地记录 05:28:34 UTC 冻结，BTS sidecar 记载随后下载。顺序与文件内容相容，但本轮没有取得当时外部不可修改的预注册证据，无法独立证明此前从未查看过结局。应表述“按 v7 已记录冻结规则复算”，不新增外部预注册/无窥视认证。

### 3.2 匹配不是随机抽样

|2026-01 至 08 总体|航段数|15 分钟观察率|60 分钟观察率|
|---|---:|---:|---:|
|TAF 可匹配|1,373,557|27.6092%|12.0091%|
|不可匹配|34,280|32.1062%|13.8186%|

覆盖 **97.5651%** 并不证明剩余 2.4349% 可忽略：不可匹配组本身风险更高。以上为事后描述，不作缺失机制随机性或因果证明；同批评分改善仅直接适用于可匹配总体。新增逐月逐机场结局构成表，后续必须按机场、时点和缺失理由处理，而不是直接推广到全部航段。

### 3.3 分数与校准须分开

同批 Brier 差（增强−静态）为 **−0.0053234913 / −0.0029721604**；与原 v7 一致。7 天配对区块探索范围分别为 [−0.00677786,−0.00421120] / [−0.00405317,−0.00214365]。区块、1000 次和 seed 是工程/统计选择；这不是已证明覆盖率的置信区间。

不利预报组 84,960 条，60 分钟观察 **28.2180%**、增强预测约 **20.82%**，仍低估约 **7.40 个百分点**。全匹配总体增强预测 11.1628%，比观察 12.0091%低约 0.85 个百分点。评分改善并未消除平均偏差。假日是日历需求代理，不是已证实际客流冲击；未触发不利标志也不等于完整预报下的好天气。

## 四、本轮新发现：TAF 结构化字段与随附文本有少量矛盾

### 4.1 来源回查顺序与定位

本轮先复算，再尝试回查 AWC、IEM、OPM 和 BTS 官方网页；HTTPS 握手失败逐项记入 `WEB_SOURCE_RETRIEVAL.json`，未关闭证书校验，也未把失败写成读过。随后经 GitHub 官方 Contents API 取得 pyIEM 原始解析模块，blob `6354576bfb86ec685d7d47ee7c53567db72ec16a`、SHA-256 `bebbf3b6902860ffca6dda08a8ab49c702f0f772e16439f60bb3c3e5b58d5242`，见 `IEM_PARSER_SOURCE.json`。

按取得快照定位：源码没有论文页码，`add_forecast_info` 使用**代码行 36–62**；`parse_prod` **170–219** 先解析初段再拆条件组；`TAFProduct.sql` **250–255 附近**对更正处理有未完全覆盖的注释。它支持应审查解析/更正版本问题的理由，**不证明当前档案的每个异常都由该段代码造成**，更不能拿当前 main 版本代替历史入库版本。源码是数据处理来源，不提升为第三篇核心研究论文。

### 4.2 对包内数据实际检查了什么

对 362,285 个标准化 prevailing 段作有限的可见文本检查：从 BKN/OVC/VV 识别云底，兼容 CB/TCU 后缀；比较结构化云底，同时找结构化 TS/FZRA 在随附文本缺席的情况。结果：

- **27 段、20 个产品**有候选矛盾；27 段云底不一致，其中 **4 段**同时出现结构化不利天气码在文本缺席。
- 例：KORD `202307220302-KLOT-FTUS43-TAFORD-AAA` 初段，随附文本只有 `P6SM FEW050 SCT100` 一类条件，结构化字段却有 −TSRA 和 4500 英尺云底。
- 例：KATL `202601071258-KFFC-FTUS42-TAFATL-AAA` 多个 FM 段共用同一随附文本而结构化云底不同，应回原发报产品逐段核对，不能任选一方当真。
- 初次简易正则未处理 CB 后缀，曾产生 3944 条云底候选；检查实例后修正为兼容 CB/TCU，得到上述 27 条。**保留这个真实诊断顺序，不把第一轮误报包装成发现。**

|阶段|匹配航段|直接匹配候选矛盾段|匹配其所在任一产品段|

524 是训练**候选池暴露**，不能冒称全部进入原 50,000 拟合抽样。直接暴露与整产品保守暴露不可混加；验证暴露集中于 2026-01。它们不是已判定错误航段数，亦不能由占比很小推出成绩影响可忽略，因为拟合和校准也涉及候选段。

本轮**没有改写输入、删异常、重新选参数或声称修复后得分**。原 Brier 是对原归档字段可重复的结果，但输入语义完全核实的门禁保持关闭。后续需取得原始 NWS 发报全文及修订身份，定位 IEM 逐组表/产品表/随附文本是否一致，区分条件组拆分、档案修订和文本关联问题。若无法定真，应保留矛盾段不可用的保守版本作敏感性，并清楚写明这是事后复核，不是新的未看验证。
